# v0.3 实现报告 — Personal Knowledge Bridge

> 状态：**已实现并通过验收**。
> 目标句保持不变：**更换模型以后，AI 的长期身份、记忆和项目状态仍然存在。**

设计文档见 [`v0.3_design.md`](v0.3_design.md)。本文只记录**实际实现**、**与设计的偏差**、**证据**和**已知限制**。

## 1. 一句话总结

Obsidian 成为一个**消费者**，不是第二个记忆库。文本流向单向：

```
vault  --import-->  Event  -->  Memory Core (SQLite)    人类 -> AI
vault  <--export--  markdown 镜像                        AI -> 人类（只读视图）
```

两条管线都是单向的，**没有 sync、没有回写、没有 watcher**。Obsidian 拥有「文本」，Memory Core 拥有「断言」。

## 2. 实际架构

```
memory_bridge/                    仅使用 Memory Core 公开 API
├── __init__.py
├── __main__.py                   python -m memory_bridge
├── config.py                     BridgeConfig（JSON，零依赖）
├── cli.py                        import / export / status
└── obsidian/
    ├── provenance.py             external_ref、内容哈希、来源块（纯函数）
    ├── vault.py                  只读扫描 + frontmatter 子集解析 + glob
    ├── chunker.py                确定性分块（标题/段落/声明边界）
    ├── classify.py               路由：knowledge / declaration / preference / project_state
    ├── importer.py               vault -> Event -> 记忆（幂等、可 dry-run）
    └── exporter.py               记忆 -> markdown 镜像（单向、可重建）
```

### 2.1 分块（`chunker.py`）

- 按标题分节，代码块内的 `#` 不算标题；
- 默认剔除围栏代码块；
- 段落是切分单位，超过 `max_chars` 时继续切；
- **声明边界**：以 `记住：` / `remember:` / `> [!memory]` 开头的段落**单独成块、且绕过最小长度限制**。

最后一条是实现中发现的关键问题。Memory Core 的规则抽取器只在文本**开头**看到 `记住：` 才会触发，而真实笔记里声明总在中间。若不做边界切分，显式声明永远走不到确定性路径，只能靠模型——这与「显式指令必须零模型可用」冲突。

同时，声明块**只包含一个段落**。规则抽取器会把「标记之后的全部内容」当作记忆内容，若把下一段并进来，就会得到一条包含两个无关陈述的非原子记忆。

### 2.2 路由（`classify.py`）

| 内容 | 判定信号 | 写入路径 | 是否经过模型 |
|---|---|---|---|
| 普通知识 | 默认 | `learn()` | **是**（NOOP 是预期答案） |
| 显式声明 | `记住：` / `remember:` / `> [!memory]` | `observe()` | **否** |
| 偏好 | frontmatter `type: preference` 或 `偏好：k = v` | `set_preference()` | **否** |
| 项目状态 | frontmatter `type: project-state` 或 `项目状态：p = {...}` | `set_project_state()` | **否** |
| 被排除 | 配置 glob | 不扫描 | — |

两个刻意的立场：

1. **大多数人类笔记不应该变成记忆。** 未标记的散文交给模型判断，而模型的正确回答通常是 NOOP。
2. **偏好和项目状态永远不经过模型。** 它们是精确的键值／单值数据，Memory Core 自己的架构（ADR 0006）就禁止概率模型写入它们。

**声明为什么不经过模型**：实测中，规则已以 confidence 1.0 抽出句子后，模型又把 `我更喜欢…` 改写成 `用户更喜欢…`。exact-content 去重抓不住改写，结果是**近似重复**。显式声明本身已经是权威，不需要模型二次猜测。

### 2.3 作用域解析优先级

frontmatter `scope:` → `persona:` → `project:` → 路径映射（`Projects/<name>/** → project:<name>`）→ `config.default_scope`。

### 2.4 幂等

| 层级 | 键 | 效果 |
|---|---|---|
| 文档 | `document_hash` | 整篇跳过（`documents_unchanged`） |
| 分块 | `content_hash` | 只跳过该块 |

两个哈希都写在 `Event.metadata` 里，用 `session_id = external_ref` 查询（`session_id` 是**已索引的真实列**）。因此幂等**不需要任何 schema 迁移**。

实测（step 5）：编辑一篇笔记后，`chunks_planned=3`、`chunks_skipped_seen=1`、`chunks_ingested=2`——未改动的块确实没有被重写。

### 3.1 `provenance` 参数（#10）——为什么必须有

Bridge 需要「这条记忆来自哪个文件」。事件的 `metadata` 只挂在事件上，而记忆的 `source` 由**候选**决定：

- 规则路径把 `origin=rule` 写进 `source`；
- 因此规则形成的记忆**拿不到** `external_ref` / `document_title`。

结果是导出镜像里最关键的声明类记忆没有 `source_ref`。这是设计阶段没有预见的接口缺口。

修法是 `_commit()` 里合并一次，**8 行**：

```python
source.setdefault("event_ids", [event.id])
if provenance:
    formed_by = source.get("origin")
    source.update(provenance)
    if formed_by and not source.get("formed_by"):
        source["formed_by"] = formed_by
```

语义划分：`origin` 表示**来自哪里**（`obsidian`），`formed_by` 表示**如何形成**（`rule` / `llm`）。信息不丢失，默认 `None` 时行为与 v0.2 完全一致。

## 7. 已知限制

诚实列出，不做粉饰。

1. **近似重复无法自动去重。** 内容被改写时（`我更喜欢…` → `用户更喜欢…`）exact-content 去重抓不住。声明路径已通过「不调用模型」规避；但**普通知识笔记**仍可能产生语义重复。真正的解法需要语义去重（v0.4 候选），当前不做。

2. **模型行为有随机性。** 演示中同一批知识笔记，dry-run 时 qwen3:8b 两次返回缺少 `memories` 键（被 schema 校验拒绝），apply 时成功。系统按设计降级（事件仍写入，可日后重新抽取），但**同一 vault 两次 apply 的记忆数可能不同**。这是 P0-1「模型输出是候选不是事实」的必然代价。

3. **`knowledge` 路由依赖模型可用性。** 无模型时只有显式声明、偏好、项目状态会形成记忆。这是**刻意的**（红线 5：完全无模型也要可用），但意味着未标记的知识笔记需要模型才进入长期记忆。

4. **幂等检查的扫描成本随历史增长。** 每个文档用 `session_id` 查历史事件（已索引，很快），但同一文档反复编辑会线性累积事件。未来应加 `sources` 表做 O(1) 查找——**现在不做**（YAGNI）。

5. **frontmatter 解析是子集。** 支持标量与列表；**不支持嵌套 map**。结构化状态请用行内 JSON（`state: {"phase": "v0.3"}`）。这是零依赖的代价，已文档化。

6. **`knowledge` 路由的去重依赖模型自觉。** 模型应当对「这只是一句普通笔记」回答 NOOP。它不是每次都听话。

7. **导出是整文件重写。** 大 vault 上每次导出都重写全部镜像文件；镜像不含独立状态，所以这只是性能问题，不是正确性问题。

8. **来源笔记被删除时不会删除记忆。** 设计如此（记忆是断言，笔记是文本）。Bridge 也**不**主动标记陈旧——被删除的文档下次导入时不会被扫描到，其记忆保持 active。`--mark-archived` 是设计中的可选功能，本次未实现。

9. **`markdown` 之外的文件未导入。** 只处理 `**/*.md`。

```powershell
py -3 -m unittest discover -s tests -t .

# 2. 一键演示（不需要模型）
py -3 scripts/demo_obsidian_bridge.py

# 3. 真实模型手动演示（对副本操作）
$vault = "$env:TEMP\demo-vault"
Copy-Item -Recurse fixtures\obsidian_vault $vault
py -3 -m memory_core --db "$env:TEMP\demo.sqlite" init
py -3 -m memory_bridge import $vault --dry-run --provider ollama --model qwen3:8b --db "$env:TEMP\demo.sqlite"
py -3 -m memory_bridge import $vault --apply   --provider ollama --model qwen3:8b --db "$env:TEMP\demo.sqlite"
py -3 -m memory_bridge export $vault --db "$env:TEMP\demo.sqlite"
py -3 -m memory_bridge status $vault --db "$env:TEMP\demo.sqlite"
```

`import` **默认 dry-run**，必须显式 `--apply` 才会写入。
